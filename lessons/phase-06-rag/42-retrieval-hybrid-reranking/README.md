## Why this matters

Retrieval is not a single “vector search” operation. A user can type an exact
error code, a paraphrase, a date, a product name, or a vague description.
Sparse lexical ranking, dense vectors, metadata filters, fusion, and rerankers
make different errors. Combining them without a component evaluation merely
moves uncertainty into a larger system.

Lesson 41 created immutable source identities, chunks, vectors, tenant
entitlements, and a manifest. This lesson consumes those artifacts and keeps
generation completely out of the experiment. That separation is important:
when an answer is wrong, you first need to know whether useful evidence was
retrieved. A fluent model can hide retrieval misses by inventing an answer,
while a poor answer can make good retrieval look bad.

You will implement BM25-style sparse scoring, the lesson-41 dense baseline,
reciprocal rank fusion (RRF), and a transparent joint query/chunk reranker.
Then you will evaluate all four paths against checked-in graded relevance
judgments. The numbers are generated by your machine from this tiny fixture;
they are not advertised performance.

The security invariant is stronger than ranking quality: tenant filtering
happens before any candidate is scored. The code refuses a configuration that
requests post-ranking filtering, and it rejects qrels that reward an
unauthorized result.

## Learning outcomes

By the end, you can:

- derive a BM25-style score from term frequency, document frequency, document
  length, `k1`, and `b`;
- explain why lexical retrieval is useful for names, identifiers, dates, and
  exact wording;
- distinguish a bi-encoder candidate retriever from a cross encoder;
- reuse normalized dense vectors without confusing similarity and relevance;
- filter by trusted tenant metadata before sparse or dense scoring;
- fuse rankings with RRF without calibrating incompatible raw score scales;
- widen candidate retrieval before reranking and explain the latency/quality
  trade-off;
- calculate recall at `k`, mean reciprocal rank, and normalized discounted
  cumulative gain;
- use graded qrels tied to an immutable corpus snapshot;
- inspect per-query failures rather than accepting only an aggregate;
- reject a contaminated evaluation that labels inaccessible evidence relevant;
- define what an optional learned cross-encoder experiment must record.

## Under the hood

### Filter before ranking

The retriever begins with:

```text
authorized = [chunk for chunk in corpus if tenant in chunk.tenant_ids]
```

Only `authorized` enters BM25, dense scoring, RRF, or reranking. This protects
more than final output. A post-ranking filter can leak through score logs,
candidate caches, timing, traces, reranker requests, or prompts. It also harms
quality: if the global top results are forbidden and removed after `top_k`,
the user may receive fewer results even though relevant authorized chunks
existed below the cutoff.

The local request includes a plain tenant string; that is not authentication.
In a deployed service, a trusted gateway maps an authenticated principal to
entitlements. Never let an unauthenticated caller grant itself a tenant merely
by setting JSON.

### BM25-style sparse ranking

For query term `t` and document `d`, the implementation uses:

```text
idf(t) = ln(1 + (N - df(t) + 0.5) / (df(t) + 0.5))

score(t,d) =
  idf(t) × tf(t,d) × (k1 + 1)
  ---------------------------------------------
  tf(t,d) + k1 × (1 - b + b × |d| / average_dl)
```

`k1` controls how quickly repeated term frequency saturates. `b` controls
document-length normalization. With `b=0`, length does not matter; with `b=1`,
the normalization uses the full length ratio. The implementation indexes
title, section heading, and chunk text as one teaching document.

BM25 is not “old and obsolete.” It often excels at exact identifiers and rare
terms. It also cannot infer arbitrary synonyms. The `snapshot-retention` query
uses “backup” while the source says “encrypted snapshots,” providing a visible
failure to investigate.

### Dense candidate retrieval

The dense path hashes the query with the same lesson-41 algorithm and takes dot
products with normalized chunk vectors. A production bi-encoder learns an
embedding function that places related query and passage meanings nearby. It
can retrieve paraphrases, but may weaken exact token signals, inherit model
bias, or behave poorly outside its training domain.

Because query and chunk embeddings are computed independently, all chunk
vectors can be prepared offline. Online cost is query embedding plus nearest
neighbor search. That independent encoding is why a bi-encoder is practical
for first-stage retrieval.

### Reciprocal rank fusion

Sparse BM25 scores and dense similarity scores do not share a calibrated
scale. RRF operates on positions:

```text
RRF(chunk) =
  sparse_weight / (rank_constant + sparse_rank)
  + dense_weight / (rank_constant + dense_rank)
```

A document appearing high in both lists accumulates evidence. A result present
in only one list can still survive. `rank_constant` reduces the difference
between adjacent early ranks. RRF is easy to inspect, but its weights and
candidate widths remain experiment variables. It cannot recover a chunk that
both candidate retrievers miss.

### Wider candidates and reranking

First-stage retrieval examines a broad collection cheaply. Reranking spends
more work on `candidate_k`, then returns `top_k`. A learned cross encoder reads
the query and candidate together through attention and predicts a relevance
score. It is usually more expressive and more expensive than a bi-encoder.

The mandatory CPU reranker is deliberately transparent. It combines:

- normalized RRF score;
- fraction of query tokens appearing in chunk text;
- fraction appearing in the section heading.

It is not a neural cross encoder and is never labeled as one. It lets you trace
candidate width, features, weights, and rank movement before downloading a
model. The optional script accepts a recorded candidate file and a pinned
Sentence Transformers cross encoder, keeping model comparison separate from
the offline baseline.

### Retrieval metrics

For a query with relevant set `R` and returned top `k`:

```text
recall@k = |returned@k ∩ R| / |R|
MRR      = 1 / rank of first relevant result, or 0
DCG@k    = Σ (2^grade_i - 1) / log2(i + 1)
nDCG@k   = DCG@k / ideal_DCG@k
```

Recall asks whether the candidate set contains relevant evidence. MRR strongly
rewards putting one relevant result early. nDCG uses graded relevance and
rewards the best evidence appearing first. A method can improve one metric and
regress another.

Aggregate means can hide query families. The generated failure report retains
query text, intent, missing relevant IDs, and observed IDs. Diagnosis should
follow the pipeline: entitlement filter, source and chunk, query, candidates,
fusion, reranker. Do not immediately blame the generator; there is no generator
in this lesson.

### Evaluation integrity

`qrels.json` includes the SHA-256 of lesson 41’s source snapshot. Relevant
chunk IDs must exist and be authorized for the query tenant. This prevents two
common confounds:

1. evaluating a new index against labels for a different corpus;
2. rewarding a retrieval result that the user must never see.

Qrels are judgments, not eternal truth. Use multiple assessors, adjudication,
clear intent definitions, and representative query sampling in a real system.

## Cost and safety

The required path is offline, standard-library Python, and a tiny corpus. It
creates no cloud resources.

The component timers use `perf_counter_ns`, but the corpus is too small for
capacity planning. Process startup, cache state, Python overhead, and system
load can dominate. Production benchmarking needs warmup, concurrency, a
representative index, percentiles, resource telemetry, and repeated trials.

The optional cross encoder downloads a model and package graph. Review its
model card and license, pin immutable artifacts, use an isolated cache, set a
spending/time limit, and retain the resolved environment. Do not send private
candidates to an external reranker without authorization.

Security cases prove only that this implementation applies its fixture
entitlements before scoring. They do not provide identity, authorization
administration, encryption, audit retention, or adversarial robustness.

## Deliberate failure

Run:

```bash
./scripts/run-deliberate-failure.sh
for file in artifacts/failures/*.txt; do
  echo "$file"
  sed -n '1,80p' "$file"
done
```

Four inputs must fail:

- `after_ranking` is rejected because authorization cannot be deferred;
- negative/zero RRF settings and insufficient candidates are rejected;
- qrels tied to the wrong snapshot and an unauthorized Alpha chunk are
  rejected.
- a zero `top_k` is rejected instead of silently falling back to the default.

Expected final line:

```text
PASS: unsafe filter stage, invalid fusion, invalid top-k, and confounded qrels were rejected
```

Recovery means restoring the pre-ranking invariant, selecting explicit
non-negative fusion weights with sufficient candidates, and relabeling against
the active authorized corpus.

## Troubleshooting

If qrels report a source mismatch, rebuild lesson 41 from the unchanged v1
corpus. If you changed source or chunking intentionally, regenerate and review
chunk judgments.

If every BM25 score is zero, print tokenized query and chunk text. Punctuation,
case, domain tokenization, and identifiers matter. Production analyzers may
need stemming, language-specific segmentation, or field weights.

If dense rankings seem arbitrary, remember the baseline is feature hashing,
not a learned semantic encoder. Inspect collisions and character features.
That result motivates a controlled model comparison; it does not justify
calling the baseline broken.

If RRF changes nothing, check candidate list diversity. Identical orderings
produce little change. If reranking changes nothing, inspect `candidate_k` and
feature weights.

If optional model loading fails, do not remove revision pinning or enable
remote code casually. Verify the model repository, revision availability,
package versions, storage, and network policy.
